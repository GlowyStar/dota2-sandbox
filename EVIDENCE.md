## Что удалось и не удалось исследовать

- **Данные (наблюдение).** Из архива игры прочитаны `scripts/npc/*` (герои, способности, предметы, юниты, нейтральные
  предметы) и английская локализация. Пакет данных, собранный из архива установленной игры, побайтно совпал с пакетом,
  собранным из независимого зеркала тех же файлов на GitHub (`tools\compare_sources.mjs`).
- **Режим «Проба героя» (наблюдение).** Прочитаны скрипты `dota_addons\hero_demo\scripts\vscripts\*.lua`. По ним составлен
  список возможностей песочницы: спавн союзника/врага/любого юнита, уровень, Scepter/Shard, обновление, бесплатные
  заклинания, неуязвимость, манекен, руны, крипы, журнал боя.
- **Код способностей (не исследован).** Логика способностей находится в скомпилированном `server.dll`. Инструменты REA
  для его разбора в этой сессии недоступны: сервер REA не подключён, а Ghidra, IDA и Java на машине не установлены.
  Поэтому поведение способностей восстановлено по текстам описаний 7.42 и значениям из данных, а не по коду.
  Это главное ограничение точности.
- **Скрипты способностей (как сделаны и чем проверены).** Каждая способность героев, предметов и крипов написана по
  тексту подсказки 7.42 из файлов игры; все числа читаются из данных по именам значений, а не вписаны руками.
  Каждый скрипт несёт метку точности (`full`, `approx`, `partial`, `n/a`) и пояснение, что упрощено или чего нет
  (сводка в `COVERAGE.md`). Проверка: числа в журнале боя сверены со значениями подсказок (несколько тысяч сверок),
  затем общий прогон `tools\hero_check.mjs` по всем 127 героям, набор тестов и случайные бои `tools\fuzz.mjs`.
  **Чего не было:** сверки с живой игрой. Метка `full` означает «все пункты подсказки смоделированы», а не
  «поведение совпало с игрой в тесте»: там, где подсказка молчит (порядок событий, округление, взаимодействие
  двух способностей), поведение в игре может отличаться.

## Типы источников

- **[K]** значение или структура взяты прямо из данных игры.
- **[F]** подгонка под независимые цифры Valve (datafeed сайта dota2.com): 127 героев, нулевое расхождение.
- **[P]** текст патчноутов, поставляемых с игрой (`patchnotes_english.txt`).
- **[W]** давно известная публичная формула, которую здесь проверить нечем.
- **[A]** допущение или упрощение симулятора.

## Допущения симулятора

| Допущение | Влияние |
|---|---|
| Ровная площадка: нет рельефа, деревьев, тумана войны, столкновений юнитов | манёвры, обзор и промахи с низины не моделируются |
| Нет поворота юнитов | время на разворот не учитывается |
| Время атак идёт по «идеальной» шкале, события привязаны к тикам | средняя скорость атаки точна, отдельные удары сдвинуты до 1/30 с |
| Дальность атаки считается с учётом радиусов юнитов, дальность каста от центра до центра | возможна погрешность в десятки единиц дальности |
| Стандартная прокачка: одно очко за уровень, ультимейт при первой возможности, затем способности поровну по порядку слотов; очки, которые некуда вложить, идут в атрибуты (до 7 раз) | у обычного героя атрибуты приходятся на 17, 19, 21, 22, 23, 24, 26 уровни; порядок можно задать явно (`skills`, `prio`) |
| Скрытые вспомогательные способности не тратят очки и следуют за способностью, чьё имя продолжают (`x_release` за `x`) | у способностей без такой пары уровень 1 |
| Пауза между использованиями зарядов: кулдаун способности, если он не больше 3 с, иначе 0,5 с | длинный кулдаун в данных относится к версии способности без зарядов; точная пауза для таких случаев не установлена |
| Преследование: атака начинается в том же тике, когда юнит дошёл до дальности атаки; начатый замах всегда завершается ударом | в игре удар ближнего боя срывается, если цель ушла слишком далеко за время замаха |
| Страх лишает действий, но юнит стоит на месте; привязь (leash) не ограничивает движение | способности со страхом чуть сильнее, чем в игре: цель остаётся в зоне поражения |
| Повторный стан короче текущего не сокращает его (то же для немоты, корней, обезоруживания, страха) | [W] |
| Эффект, который срабатывает в момент окончания действия, пропускается, если скрипт сам это не компенсирует | авторы скриптов компенсируют; правило описано в `docs/AUTHORING.md` |
| `freeSpells`: нет маны и кулдаунов у применяемых способностей; у пассивных эффектов внутренние кулдауны остаются, ИИ применяет каждую способность не чаще раза в секунду | иначе бой превращается в бесконечный поток кастов |
| ИИ: ближайшая цель, все готовые способности по приоритету, иначе автоатака | игроки действуют умнее; для точных комбо есть песочница с ручными приказами и среда для нейросетей |
| Невидимость по умолчанию не скрывает юнитов (`detectAll`) | способности на невидимость дают только свои числовые бонусы; True Sight не моделируется |

## Сверка с живой игрой (19.11.2026, клиент 6983)

Эталон — сама игра. Одна и та же сцена (юниты, позиции, приказы по времени) записывается в «Пробе героя» и в симуляторе,
сравниваются: каждый экземпляр урона (время и величина после снижений), касты (мана, перезарядка, точка каста), состояния
(стан, немота, корни…), статы по времени, потраченная мана, позиции. Инструменты: `tools/live/` (описание в
`docs/LIVE_VERIFICATION.md`), правила для скриптов: `docs/AUTHORING.md`, пометка `[L]` в коде = измерено в игре.

Итог на конец сессии (`node tools/live/compare_all.mjs`, сцены записаны рекордером версии 3):

| Набор | Сцен | Совпали полностью |
|---|---|---|
| Способности героев (по одной на способность + варианты с талантами, Scepter, Shard) | 1495 | 1077 (72%) |
| Предметы | 365 | 320 (88%) |
| Способности крипов, призывов и Рошана | 148 (111 юнитов есть в игре) | 41 |

Кроме того, статы всех героев на уровнях 1–30 сверены с игрой (здоровье, мана, реген, броня, скорость атаки, урон,
базовое сопротивление магии); 95 521 из 95 687 значений способностей совпадают с тем, как их считает игра.

Правила движка, установленные измерением в игре (`[L]`): очки навыков и бонус +2 ко всем атрибутам на уровнях
15/16/17/19/20/21/22; здоровье и мана от целых очков атрибутов, урон от целых очков в одинарной точности; стоимость маны
округляется вниз; пауза между зарядами по таблице игры; зона способности задевает юнита краем тела (радиус + размер
модели); Cleave режется бронёй каждой задетой цели; заклинание по цели под BKB проходит (мана и перезарядка тратятся,
магический урон проходит, непробивающие дебаффы не действуют, чистый урон 0); манекен «Пробы героя» бессмертен и
восстанавливает здоровье через тик; ограничение скорости может опускаться ниже 100. Сотни частных фактов о конкретных
способностях записаны в комментариях `[L]` в скриптах.

Почему не 100%:
- **Случайность.** Обычные атаки катят урон, криты и баши срабатывают по шансу: такие сцены не совпадают удар в удар,
  хотя величины на сработавших ударах и средние совпадают (около 380 расхождений из 2071 по героям).
- **Нет в движке:** направление взгляда (facing), видимость, деревья и рельеф, столкновения юнитов (куда выталкивает
  после блинка), состояние «неуязвим к атакам без разоружения», векторное наведение, альтернативный каст, скорость каста,
  страх с реальным бегством, магическая часть внутри одного экземпляра атаки. Отсюда в основном расхождения позиций и
  части таймингов.
- **Время полёта снарядов и волн** иногда отличается на 0.1–0.4 с (второй приоритет по постановке задачи).
- **Не записаны:** сцены Timbersaw (12) и часть сцен Io (4): клиент вылетал при уборке этих героев в конце сцены.
- **Крипы:** главная причина расхождений — часы матча в «Пробе героя»: демо идёт часами, нейтралы и Рошан растут со
  временем, а симулятор считал сцены с 0:00. Рекордер теперь записывает часы, сравнение подставляет их в симулятор;
  сцены перезаписаны, совпадают 41 из 148. Сцены Рошана расходятся только тем, на каком ударе сработал баш (шанс 15%),
  все его числа совпадают. Части способностей призывов (Necronomicon, Tornado) в игре у созданных скриптом юнитов
  уровень 0: проверить их можно только новой записью. Ещё 37 сцен — событийные юниты
  (гриверы, Хэллоуинский Рошан, звери Нового года), которых в живой игре нет. Измерено: прирост урона Рошана 7 в минуту
  (а не 6), золотое усиление нейтралов утраивает, юниты, созданные скриптом, остаются с 1-м уровнем способностей.

## Не установлено

- Точное квантование атак и кастов по тикам в настоящем движке.
- Порядок применения нескольких модификаторов одного значения (талант, Scepter, Shard одновременно).
- Правила округления дробных атрибутов и урона.
- Какие именно срабатывания используют PRD, а какие честный случай.
- Поведение каждой способности в пограничных случаях (например, взаимодействие с иммунитетом к эффектам): описания
  не покрывают всё, а код не разобран.

## Как повысить точность дальше

1. Закрыть способности с пометкой `partial` (список с причинами в `COVERAGE.md`): большинству не хватает одного из
   механизмов движка (True Sight, деревья, движение под страхом, применение способностей в оглушении).
2. Сверка с живой игрой: запускать те же сценарии в настоящей «Пробе героя» скриптом и сравнивать журналы боя.
   Это единственный способ проверить правила с пометкой [W] и [A].
3. Разбор `server.dll` через REA с установленным Ghidra, если понадобится точная формула конкретной способности.
